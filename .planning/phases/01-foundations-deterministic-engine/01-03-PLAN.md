- CLI argument parsing: `process.argv.slice(2)`, with optional `--dir <path>`. Anything else is an unknown argument: print usage to stderr and exit 2.
Edge/error cases:
- An empty data dir reports `missing required content file` for `items.json`.
- `items.json` containing `[]`, or `{v:1, items:[]}`, is a schema error (items min 1).
- A negative or fractional price, a name that is empty or longer than 40 chars, an uppercase id, an unknown `kind` and an extra key are each rejected. Test each one.

  <action>
1. `schemas/common.ts`: `export const IdSchema = z.string().regex(/^[a-z][a-z0-9-]{0,47}$/, "id must be kebab-case, start with a letter, max 48 chars");`.
2. `schemas/items.ts`:
   - `ItemSchema = z.strictObject({ id: IdSchema, name: z.string().min(1).max(40), kind: z.enum(["consumable","gear","joke"]), price: z.number().int().min(0), description: z.string().min(1).max(200) })`.
   - `ItemsFileSchema = z.strictObject({ v: z.literal(1), items: z.array(ItemSchema).min(1) })`.
   - `export type Item = z.infer<typeof ItemSchema>`.
3. `registry.ts`: `export const CONTENT_REGISTRY = { "items.json": ItemsFileSchema } as const satisfies Record<string, z.ZodType>;`. Also export `REQUIRED_FILES = Object.keys(CONTENT_REGISTRY)`, sorted.
4. `validate.ts`: export `ContentEntry`, `ContentError` and `validateContent(entries)`.
   1. Unknown files produce an error.
   2. Each registered file missing from `entries` produces an error.
   3. `data === undefined` produces `invalid JSON`.
   4. Otherwise run `schema.safeParse(data)`; on failure, map each issue to `{file, path: issue.path.join("."), message: issue.message}`.
   5. On success, run the generic duplicate-id check.
   6. Return the errors sorted by `file`, then `path`, for deterministic output.
5. `index.ts`: re-export the schemas, types, registry and validate. Remove `PACKAGE_NAME`. **Do not** export from `./load`.

<task type="auto">
  <name>Task 2: Loader, validate CLI, sample data and build gate</name>
  <files>packages/content/src/load.ts, packages/content/scripts/validate.ts, packages/content/data/items.json, packages/content/package.json</files>
  <action>
1. `src/load.ts`: `loadContentDir(dir: string | URL): ContentEntry[]`.
   - Uses `readdirSync(dir)` filtered to `*.json` and sorted.
   - For each file, reads it with `readFileSync(new URL(name, dirUrl))` or `path.join`, depending on the input type. Normalize a URL input to a path with `fileURLToPath`.
   - `JSON.parse` goes in a try/catch; on failure, `data: undefined`.
   - A missing dir throws with the message `content dir not found: <dir>`.
2. `scripts/validate.ts`: parses `--dir` (resolved with `path.resolve(process.cwd(), value)`), defaulting to `fileURLToPath(new URL("../data/", import.meta.url))`.
   - Calls `loadContentDir` and then `validateContent`.
   - Prints `✗ ${file} ${path}: ${message}` per error and exits 1.
   - On success prints `✓ content valid (${n} files)` and exits 0.
   - An unknown argument prints `usage: validate [--dir <path>]` to stderr and exits 2.
   - A loader throw prints `error: <message>` to stderr and exits 2.
3. `data/items.json`: `{"v":1,"items":[...]}` with 5 consumables from the design doc's Consumables table:

   | id | name | price | description |

   | `smoke-bomb` | Smoke Bomb | 50 | Guarantees escape from battle. |

   Every entry has `kind: "consumable"`.
